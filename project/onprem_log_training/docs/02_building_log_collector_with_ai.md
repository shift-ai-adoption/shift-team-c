# AIエージェントでログ収集ツールを作るときのポイント

## この資料の目的

この環境には、ログを収集・分析するツール(ログコレクター)はあらかじめ用意されていません。
学習者はAIエージェントに指示を出しながら、そのツールを自分で組み立てていきます。
ここでは、その際に押さえておくべきポイントと、プロンプトに書くべき事項を整理します。

## なぜ「いきなり作って」ではうまくいかないか

AIエージェントは、指示された範囲でしか動けません。「ログ収集ツールを作って」だけでは、

- どこのログを見ればいいのか
- 複数のログをどうやって同じインシデントとして結びつければいいのか
- SSHでどこに、どうやって接続すればいいのか

といった、この環境固有の前提をAIエージェントが知らないため、的外れな実装になったり、
毎回同じ質問をされて手戻りが発生したりします。良いプロンプトは、これらの前提を
最初にまとめて渡すことで、AIエージェントが一度で正しい方向に進めるようにします。

## 押さえておくべきポイント

### 1. ログの発生源は2箇所に分かれている

- `client/logs/app.log`(ローカルファイル、SSH不要)
- `server`コンテナ内の `/app/logs/service.log`(SSH経由でのみアクセス可能)

この2つは「別サーバーのログ」を模しているため、両方を見に行く前提でツールを設計する
必要があります。片方だけ見て満足するツールは不完全です。

### 2. 突き合わせのキーはTrackID

2つのログをどう結びつけるかが最大のポイントです。この環境では `TrackID:XXXXXXX`
(英数字7文字)という共通のキーが両方のログに出現するよう設計されています。
「タイムスタンプが近いログを探す」といった曖昧な方法ではなく、**このIDで正確に一致させる**
ことが本来のログ収集ツールが目指すべき動作です。

### 3. SSH接続はAIエージェントに任せてよい

学習者自身がSSHコマンドや鍵の扱いを覚える必要はありません。この環境には
`AGENT_SSH_GUIDE.md` という、AIエージェント向けの接続情報(ホスト・ポート・鍵のパス・
ログのパス)をまとめたファイルが用意されています。プロンプトの中でこのファイルを
読ませる、あるいは中身を貼り付けることで、AIエージェントはSSH接続の詳細を自力で
調べる必要がなくなります。

### 4. 「検知」「収集」「関連付け」「出力」の4段階で考える

ログ収集ツールは、次の4つの機能に分けて考えると設計しやすくなります。

| 段階 | やること | この環境での具体例 |
|---|---|---|
| ① 検知 | 異常の発生に気づく | `app.log` の `ERROR` 行を見つける |
| ② 収集 | 関連するログを集める | 該当TrackIDで `service.log` を検索する |
| ③ 関連付け | 複数ログを1件にまとめる | TrackIDをキーに集約する |
| ④ 出力 | 結果を人が読める形にする | 一覧・レポート・通知など |

最初から全部を一度に作らせようとせず、まず①②だけを動かし、うまくいったら③④を
追加していく、という段階的な進め方がAIエージェントとの協働では効果的です。

### 5. 常時監視の仕組みは別に検討する

「一定間隔でログを確認し続ける」という常駐処理を作る場合、以下のような選択肢があり、
どちらを選ぶかでプロンプトの書き方が変わります。

- Node.jsなどで常駐プロセスを新規に書く(`fs.watch` やポーリングなど)
- Claude Codeの `/loop` のような、一定間隔でエージェントに指示を再実行させる仕組みを使う

どちらが良いかは決まった正解ではなく、学習者自身がAIエージェントと相談しながら
選ぶ部分です。

## プロンプトに書くべき事項(チェックリスト)

AIエージェントに依頼する際は、次の情報を最初に伝えると手戻りが減ります。

- [ ] **目的**: 何のためのツールか(例:「client/serverの2つのログをTrackIDで紐づけて、
      1件のインシデントとしてまとめたい」)
- [ ] **ログの場所**: `client/logs/app.log`(ローカル)と、`server`側のログ(SSH経由、
      `AGENT_SSH_GUIDE.md` を参照させる)
- [ ] **突き合わせのキー**: `TrackID:` に続く英数字7文字であること、正規表現
      `TrackID:([A-Z0-9]{7})` で抽出できること
- [ ] **検知条件**: どの行を「異常」とみなすか(例: `ERROR` を含む行)
- [ ] **実行環境の制約**: SSH接続はパスワードなしの鍵認証であること、対話ログインではなく
      コマンドを直接実行する形で十分であること
- [ ] **スコープ**: 今回作るのは検知/収集/関連付け/出力のどこまでか(段階的に依頼する)
- [ ] **出力形式**: 結果をどう見せたいか(コンソール表示、ファイル出力、JSON形式など)

## プロンプト例

```
projects/onprem_log_training/ 配下に、client/server 2つのログをTrackIDで
関連付けるログ収集ツールを作りたい。

- client側のログ: client/logs/app.log (ローカルファイル)
- server側のログ: AGENT_SSH_GUIDE.md に書かれているSSH接続情報を使って取得すること
- 突き合わせのキー: 両ログに共通で出現する TrackID:XXXXXXX (英数字7文字)
- まずは以下の範囲だけ実装してほしい:
  1. client側ログから ERROR 行を検知する
  2. そのTrackIDでserver側ログを検索する
  3. 両方のログをTrackID単位でまとめて標準出力に表示する
- 常時監視の仕組みは今回はまだ不要。1回実行して結果が出れば十分。
```

このように、目的・ログの場所・キー・スコープを明示すると、AIエージェントは
迷わず実装に着手できます。
